## 一、任务要求

- **需求背景**：任务1（SVG 极简系列 01~05）与任务2（SVG 水墨强化系列 06~10）均已完成并评审通过，但用户评估 **SVG 矢量方案整体效果不足**，决定转向文生图（AIGC）路线生成 logo 底稿：由主流文生图模型（Midjourney / DALL·E / Stable Diffusion / 通义万相等）生成水墨风 logo 底稿，后续再考虑矢量重绘/人工精修。本任务为该路线的**前置提示词工程**：产出一份可直接投喂模型的详细提示词文档。
- **目标**：产出一份**可直接投喂主流文生图模型的提示词工程文档**（`design/河图Logo文生图提示词.md`），完整覆盖用户 4 项要求，包含中文主提示词、英文对照版、参数建议、变体微调方向、模型适配与翻车规避使用说明，并配套文档文本断言单元测试。
- **用户 4 项核心要求（缺一不可）**：
  1. **横向卷轴画卷**：主体为横向展开的卷轴画卷（半展开/完全展开横卷，含轴杆、卷面，延续任务1 方案 1/3 的横向卷轴基因）；
  2. **画卷上是水墨风的 K 线图**：K 线以毛笔/水墨笔触绘制，蜡烛形态（影线+实体）可辨识，非机械几何直边；
  3. **一个曲折向上的红色箭头**：朱砂/红色箭头，走势带回调、蜿蜒曲折后总体向上，寓意"规律在波动中被发现"（延续任务1 方案 3 朱砂上升箭头母题）；
  4. **极简中国水墨风**：宣纸底 + 墨色晕染 + 大量留白 + 克制用色（墨色 + 朱砂点睛），拒绝堆砌。
- **验收标准**（沿用前两期的 A/B/C 三类框架，全部满足才算通过；A 类单测对象为 **markdown 文档文本内容断言**，与任务1/2 的 SVG/XML 断言明确区分）：

  **A. 交付物验收（可被单元测试断言，硬门禁，共 15 个用例，见第七节）**：
  1. 交付物存在：`design/河图Logo文生图提示词.md` 存在、可读、非空（A1）；
  2. 结构章节齐全：文档含 6 个必需章节——主提示词 / 英文提示词 / 负面提示词 / 参数建议 / 变体微调方向 / 使用说明（A2）；
  3. 中文主提示词覆盖 4 项必需要素（6 个关键词锚点全部命中，锚点口径见四 §4.2）（A3）；
  4. 主提示词长度 100~500 字（去空白字符计，边界含）（A4）；
  5. 主提示词 8 段结构标记齐全：主体→构图→风格→色彩→质感→光线→细节→质量词（A5）；
  6. 负面提示词含 5 个指定禁词：text / watermark / 3d / photorealistic / clutter（A6）；
  7. 英文版存在且含关键英文词：scroll 与 arrow 必含，k-line（或 kline/candlestick）、ink、minimalist 至少 1 项（A7）；
  8. 参数建议含宽高比（`--ar` 或 `1:1`/`2:3`/`16:9` 任一）与风格权重（`--stylize` 或 `stylize`）（A8）；
  9. 变体 3~5 个且各含可替换/追加提示词片段（A9）；
  10. 使用说明含模型适配（至少覆盖 2 个模型：MJ/SD/通义万相）与翻车规避（乱码/拼贴/风格不统一至少 1 项）（A10）；
  11. 无敏感违规内容：全文暴力/色情/政治敏感黑名单词零命中（A11）；
  12. **无 SVG 产出**：任务目录 `design/` 下无任何 `.svg` 文件（与任务1/2 区分的关键断言）（A12）；
  13. 正文为 UTF-8 可读 markdown，无乱码字节（A13）；
  14. 反案例 2 个：缺"负面提示词"章节的文档校验失败；主提示词长度 99/501 字校验失败（A14，验证测试自身有效性）；
  15. 边界案例 2 个：主提示词恰好 100 字 / 恰好 500 字均通过（A15）。

  **B. 文档质量验收（节点4 评审人工判定，软门禁）**：
  1. **专业度与可投喂性**：8 段结构完整、术语准确、分层清晰，可直接复制投喂 MJ/SD/通义万相任一模型，无需二次改写；
  2. **河图体系定位契合**：卷轴母题、朱砂点睛、留白气韵、K 线+上升箭头量化语义与一二期视觉基因一致，呼应"秩序图谱、规律抽象"定位与座右铭"河出图，洛出书，圣人则之"；
  3. **变体差异明显**：5 个变体方向互不相同（形态/疏密/留白/印章/画幅比例），非近义改写、非同图微调；
  4. **负面提示词完备**：覆盖文字乱码/水印/3D/写实/杂乱 5 类常见翻车，并可扩展（no logo、no border、no signature 等）；
  5. **英文版质量**：非机翻生硬堆词，符合 MJ 风格描述词习惯（或明确标注 SD tag 形式）；
  6. **使用说明可落地**：各模型适配步骤、参数对照、翻车现象→处置手段清晰，无含糊表述。

  **C. 流程验收（硬门禁/编排器固化）**：
  1. 单元测试全部通过并写入 `.gate.json`（`test_passed=true`，15/15）；
  2. 评审 APPROVE；研发日志、资产沉淀（品牌文档第三期章节 + 资源地图第八节登记）、钉钉通知依次完成；
  3. 产出统一归档到任务目录 `opencode_schedule/20260804/20260804任务3河图Logo文生图提示词/`；
  4. **只读约束**：不修改任务1/任务2 任何文件（SVG、单测、任务书等保持原状）；不新增任何 `.svg`/`.xml` 设计文件。

### 4.6 使用说明章节要求（对应 A10）

须包含两块内容：
1. **模型适配**：至少覆盖 2 个模型（建议 MJ / SD / 通义万相三选二或全写）——各自的中英文提示词投喂方式、参数写法差异（MJ `--ar/--stylize/--no` vs SD positive/negative + CFG vs 通义万相中文直投 + 参数面板）；
2. **翻车规避**：至少覆盖 3 类现象——①文字乱码（负向加 no text、避免在画面描述中出现字形词）；②元素拼贴/割裂（元素种类克制 ≤ 5 类、构图词用"居中/单主体"）；③风格不统一（统一墨阶与用色词、避免中英混写与多风格并列词）；鼓励补充：K 线被读成条形码（加 hand-drawn candlestick 类词）、红色箭头过细被吞（加 bold/朱砂色词）等。

### 4.7 待确认项（执行前与编排者/用户确认，不阻断任务启动）

1. **出图范围**：本任务仅产出提示词文档，**不实际调用文生图模型出图**；实测生成与效果回评由用户后续另行安排（本任务交付后用户可自行投喂验证）；
2. **模型主攻方向**：默认按多模型兼容撰写（MJ/SD/通义万相通用）；若用户指定单一主力模型（如仅 Midjourney），评审前须确认调整；
3. **变体数量**：默认 5 个方向；评审可裁定精简为 3 个（A9 断言区间 3~5，均合规）。
