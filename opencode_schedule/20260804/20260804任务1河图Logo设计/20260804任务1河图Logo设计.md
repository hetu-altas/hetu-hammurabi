## 一、任务要求

- **需求背景**：hetu 系列是量化投研基础设施体系，由 hetu-aether（河图·以太，量化数据处理基础设施工具集）、hetu-mercury（河图·墨丘利，金融市场数据接口管理与同步系统）、hetu-thoth（河图·透特，投研非结构化数据处理系统）三个业务项目构成，`hetu-hammurabi` 为体系宪章编程 harness 模块。体系座右铭"河出图，洛出书，圣人则之"——河图即宇宙秩序图谱、万物规律抽象。目前体系缺乏统一的品牌视觉标识，需要设计一款体现体系定位的 Logo，并产出多个备选供决策。
- **目标**：为河图体系设计品牌 Logo 的 SVG 设计资产，**一次性生成 5 个备选方案**（纯矢量、自包含、可直接使用），并附设计说明，供后续选定主标识。
- **需求要点（4 项设计约束，缺一不可）**：
  1. **中国传统卷轴意象**：以卷轴（画轴/展开的卷轴画幅/卷轴轴杆）为核心视觉母题，呼应"河图"作为"图谱、典册"的意象；
  2. **中式极简风格**：大量留白、克制的线条与色块、对称或均衡构图，避免繁复装饰；
  3. **科技感**：通过网格点阵、数据轨迹线、发光/渐变描边、几何精确排布等元素体现数字化、基础设施属性；
  4. **量化投资要素**：至少融入以下要素中的 1~2 种——K 线（蜡烛图形态）、数据点阵、趋势曲线（波动折线）、回测网格、上升箭头、周期刻度；推荐将"河图五方点阵"（河图数理星点的抽象）与 K 线/曲线结合，同时呼应座右铭。
- **验收标准**（分三类，全部满足才算通过）：

  **A. 交付物验收（可被单元测试断言，硬门禁）**：
  1. `design/` 目录下**恰好 5 个** SVG 文件，命名 `hetu_logo_01.svg` ~ `hetu_logo_05.svg`，另含 1 份 `design/设计说明.md`；
  2. 每个 SVG 为合法 XML（`xml.etree.ElementTree` 可解析），根元素为 `<svg>`，标签闭合配对；
  3. 每个 SVG 的 `viewBox` 为 `0 0 500 500` 或 `0 0 1024 1024`（宽高相等），且 `width`/`height` 声明与 viewBox 比例一致（可为具体像素或省略/100%）；
  4. **自包含**：无 `<image>` 位图引用、无 `url(...)` 外链、无 `<link>`/`@import` 外部样式表引用；文本若使用 `font-family`，仅限通用安全字体族（serif/sans-serif/monospace 或中文字体族名），不得依赖外部字体文件；
  5. **卷轴意象可断言**：每个 SVG 中卷轴元素统一放在以 `id="scroll-"` 开头的分组 `<g>` 内（如 `id="scroll-body"`、`id="scroll-roll"`），以便测试断言"含卷轴意象元素"；
  6. **颜色受控**：每个 SVG 中 `fill`/`stroke` 属性引用的去重颜色数量（含 `#RRGGBB`、`#RGB`、`rgb()`、`url(#渐变)`）**≤ 8 种**；
  7. **风格一致性**：5 个方案共享同一主色（建议墨黑/玄青系为主色、朱砂红或金为点缀色、宣纸米白为底，具体色值在实施计划中固化并保持 5 个文件一致）。

  **B. 设计质量验收（节点4 评审人工判定，软门禁）**：
  1. 卷轴意象一眼可辨，且与量化/科技元素融合自然，不拼贴生硬；
  2. 中式极简：留白充足、线条克制、无多余装饰；
  3. 科技感明确：网格/点阵/轨迹/发光至少呈现其一；
  4. 量化投资要素可辨识：K 线/曲线/点阵/网格至少呈现其一；
  5. 整体气质契合河图体系"秩序图谱、规律抽象"的定位；
  6. 5 个方案差异明显（构图/母题演绎不同），不是同一图样的微调。

  **C. 流程验收（硬门禁/编排器固化）**：
  1. 单元测试全部通过并写入 `.gate.json`（`test_passed=true`）；
  2. 评审 APPROVE；研发日志、资产沉淀、钉钉通知依次完成；
  3. 产出统一归档到任务目录 `opencode_schedule/20260804/20260804任务1河图Logo设计/`。

## 四、设计规范 / 数据格式定义

- **文件格式**：SVG 1.1 纯矢量文本文件，UTF-8 编码；除 SVG 内联样式外不使用任何外部资源。
- **画布规格**：`viewBox="0 0 500 500"` 或 `viewBox="0 0 1024 1024"`（5 个文件可混用两种尺寸，但单文件内必须宽高相等）；建议 `width="100%" height="100%"` 或省略，交由 viewBox 控制。
- **颜色**：全文件去重颜色 ≤ 8 种；5 个方案共享同一主色板（建议 2~4 色，极简优先）；渐变使用 `<linearGradient>/<radialGradient>` 内联定义并登记进颜色计数。
- **卷轴元素约定**：卷轴相关元素（轴杆、卷面、画幅、绦带等）必须包裹在以 `id="scroll-` 开头的 `<g>` 分组中（一个文件至少一个此类分组）。
- **量化要素约定**：K 线/曲线/点阵/网格等量化元素建议包裹在 `id="quant-` 开头的 `<g>` 分组中（不强制作断言，便于评审人工核对）。
- **文本使用**：尽量不用文字；确需文字时仅用通用安全字体族（serif/sans-serif/monospace），避免依赖外部字体。
- **命名规则**：文件 `hetu_logo_0N.svg`；`<svg>` 根标签建议带 `xmlns="http://www.w3.org/2000/svg"` 与 `role="img"`、`aria-label="河图"` 属性。
- 本任务**无输入接口、无数据库读写、无网络调用**（纯设计产出），因此本模板"接口与数据格式"章节以"设计规范"替代。

## 七、单元测试

测试文件：`unit_test/test_logo_svg.py`（使用标准库 `unittest`，遵守 `constitution/unit_test/unit_test.md`）
结果保存到 `unit_test/test/test_logo_svg_result.txt`，节点3 写 `.gate.json`（`test_passed=true` 方可通过硬门禁）。

必须覆盖三大类用例：

| 类别 | 用例 | 断言要点 |
|------|------|---------|
| 正常案例 | `test_five_svg_files_exist` | `design/` 下恰好 5 个 `hetu_logo_0N.svg`，命名精确匹配 |
| 正常案例 | `test_svg_xml_well_formed` | 每个文件可被 `xml.etree.ElementTree.fromstring` 解析，根标签为 `svg` |
| 正常案例 | `test_viewbox_valid` | `viewBox` 存在且为 `0 0 500 500` 或 `0 0 1024 1024`（宽高相等） |
| 正常案例 | `test_self_contained` | 无 `<image` 元素、无 `url(`、无 `<link`/`@import`、无外部字体引用 |
| 正常案例 | `test_scroll_imagery_present` | 每个文件存在 `id` 以 `scroll-` 开头的 `<g>` 分组 |
| 正常案例 | `test_color_count_controlled` | 每个文件去重颜色数（fill/stroke 的 `#`/`rgb`/`url(#grad)` 引用）≤ 8 |
| 反案例 | `test_reject_invalid_xml` | 临时构造非 XML 文件断言解析抛 `ParseError`（验证测试自身有效性） |
| 反案例 | `test_reject_missing_viewbox` | 构造缺 viewBox 的 SVG 断言断言失败路径生效 |
| 边界案例 | `test_viewbox_boundary_sizes` | viewBox 恰为 500 与 1024 两个边界值时均通过 |
| 边界案例 | `test_color_count_boundary` | 颜色数恰为上限 8 时通过、9 时失败（阈值边界） |

> 说明：反案例与边界案例通过 `tempfile` 构造临时 SVG 文本验证测试逻辑本身可靠，不依赖真实设计文件。
