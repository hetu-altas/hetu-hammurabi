## 一、任务要求

- 需求背景：当前 harness 体系（hetu-hammurabi 的 `.opencode/{agents,commands,skills,plugin}`、`constitution/`、`docs/harness/`、`scripts/install_harness.sh`、`templates/task_book.md`）在 9 个代理提示词、6 个技能 SKILL.md、安装脚本、资源地图、宪法、模板、6 篇 harness 文档中大量**写死具体项目名与相对路径**（`../hetu-hammurabi/...`、`hetu-aether`、`hetu-mercury`、`hetu-thoth`、`../venv-hetu`），导致：① 新平级项目（如 2026-08-09 新建的 hetu-sybil）无法直接获得 harness 支持；② 资源匹配规则只认 mercury/thoth，不通用；③ 安装脚本宿主判定写死、软链范围不全（`.opencode/package.json`、`node_modules`、`package-lock.json` 不在软链范围，各项目为手工拷贝，不随 harness 更新）。
- 目标：建立「运行时项目拓扑解析」机制（.harness-env），将全部写死路径改为动态解析 + 回退规则，使 harness 支持所有与 hetu-hammurabi 平级的 hetu-* 项目，并同步修订全部写死文档表述。
- 验收标准：
  1. 新增 `scripts/harness_topology.py`（纯函数拓扑解析）与 `unit_test/test_harness_topology.py`，单测全部通过并落盘 `unit_test/test/` 结果文件，作为门禁；
  2. `scripts/install_harness.sh` 改造后：宿主判定不再写死 hetu-hammurabi（改为「含 `.opencode/agents` + `constitution/` + `docs/资源地图.md` 的目录」），目标范围为同父目录下除宿主外的全部项目（hetu-* 前缀 + 可选参数），为每个业务项目生成 `.opencode/.harness-env`，软链覆盖 agents/commands/skills/plugin/package.json/package-lock.json（node_modules 策略见待确认项 2）；
  3. 全仓 grep 收敛：9 个 agents + 6 个 skills + 资源地图 + constitution + task_book 模板 + 6 篇 harness 文档中，不再出现写死的 `../hetu-hammurabi/`、`hetu-aether`、`hetu-mercury`、`hetu-thoth`、`../venv-hetu` 业务路径引用（`grep -rn "hetu-hammurabi\|hetu-aether\|hetu-mercury\|hetu-thoth\|venv-hetu"` 于上述文件域，仅允许出现在解释性文字/历史记录中）；
  4. hetu-sybil（新建项目）执行 install 后具备完整 harness 能力：`/dev` 命令可用、资源地图可解析、.harness-env 生成正确；
  5. charter-analysis / charter-taskbook 技能的资源匹配顺序改为「先当前项目 src/docs → 再扫平级业务项目」，不再写死 mercury/thoth。

## 四、接口 / 数据格式定义

### 4.1 `.opencode/.harness-env` 格式（install_harness.sh 生成，agents/skills 读取契约）

```bash
# 由 install_harness.sh 自动生成，勿手改
PROJECT_NAME=<当前项目名，如 hetu-sybil>
PROJECT_DIR=<当前项目绝对路径>
WORKSPACE_DIR=<同父目录（所有 hetu-* 平级项目的根）绝对路径>
HARNESS_DIR=<harness 宿主项目绝对路径>
AETHER_DIR=<公共工具项目绝对路径，缺省回退：同父目录下 hetu-aether>
VENV_BIN=<共享虚拟环境 python 绝对路径，缺省回退：同父目录下 venv-hetu/bin/python>
```

- 生成时机：`install_harness.sh` 每次执行时重写各业务项目 `.opencode/.harness-env`。
- 读取规则（写入全部 agents/skills）：先 `cat .opencode/.harness-env` 解析；文件缺失/字段缺失时按回退规则动态查找——① 同父目录含 `constitution/` + `.opencode/agents` + `docs/资源地图.md` 的 `hetu-*` 目录为宿主；② `hetu-aether` 为公共工具项目；③ 当前目录 basename 为项目名。

### 4.2 scripts/harness_topology.py 纯函数接口

| 函数 | 入参 | 返回 | 说明 |
|------|------|------|------|
| `detect_host_dir(workspace_dir)` | 同父目录路径 | 宿主项目绝对路径 | 判定条件：含 `.opencode/agents/` 且 `constitution/constitution.md` 且 `docs/资源地图.md`；多个命中取含 `constitution/` 目录层级最完整者，否则报错 |
| `list_target_projects(workspace_dir, host_dir, extra=None)` | 同父目录、宿主、可选追加项目名 | 目标项目绝对路径列表 | `hetu-*` 前缀目录且非宿主；`extra` 追加指定（如非 hetu-* 前缀项目） |
| `resolve_aether_dir(workspace_dir)` | 同父目录 | hetu-aether 路径 | 缺失返回 None（调用方回退） |
| `resolve_venv_bin(workspace_dir)` | 同父目录 | venv-hetu/bin/python 路径 | 缺失返回 None（调用方回退） |
| `build_env_content(project_dir, workspace_dir, host_dir)` | 见上 | .harness-env 文本 | 含 4.1 全部字段，绝对路径 |
| `parse_env_content(text)` | .harness-env 文本 | dict | 供单测与未来插件复用 |

- 边界约定：路径含空格需引号包裹；字段值一律绝对路径；`PROJECT_NAME` 取目录 basename。

## 五、Shell 脚本

```bash
# 安装/重装 harness 到全部平级业务项目（含 .harness-env 生成与软链补全）
bash scripts/install_harness.sh
# 仅安装到指定项目（支持非 hetu-* 前缀项目）
bash scripts/install_harness.sh hetu-sybil
# 验证某个项目拓扑解析结果（调试用）
python scripts/harness_topology.py --dump /path/to/project
```

- `install_harness.sh` 内调用 `python scripts/harness_topology.py`（或 `source` 其输出的 env 模板）生成 `.harness-env`，随后执行软链：`agents`、`commands`、`skills`、`plugin`、`package.json`、`package-lock.json`（node_modules 策略见待确认项 2）。
- 宿主判定逻辑在 `harness_topology.py::detect_host_dir`，脚本内不再出现 `hetu-hammurabi` 字面量（仅注释中允许说明性文字）。
- 脚本须保持 `set -euo pipefail`，并在生成 `.harness-env` 后输出「项目名 → HARNESS_DIR/AETHER_DIR/VENV_BIN」对照表便于核查。
