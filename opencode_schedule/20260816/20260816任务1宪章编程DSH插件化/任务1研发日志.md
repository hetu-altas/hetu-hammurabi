# 任务1研发日志 · 宪章编程DSH插件化

## 一、任务概述

将宪章编程体系在 DSH 侧的分散挂接（绝对路径 .ts 插件 + 手工 patch）整合为官方组合包
`@hetu-altas/ConstitutionCoding-Plugin`：/cc 命令、硬门禁（tools/pre-execute）、看板数据通道、
看板自启钩子 + client 半区（看板面板、流程状态栏），实现 `dsh plugin` 一条命令安装、
profile 零手工配置。

## 二、创建/修改文件清单

见任务书第三节（plugins/constitution-coding/ 9 个源文件 + 测试 + 6 个文档修改）。

## 三、核心设计

1. **双面组合包**：node 半区（command/gate/status-api/dashboard-launcher/lib + index 入口）、
   client 半区（client.js），`dsh.bundle.patch` 声明配置层，`dsh.client` 声明浏览器半区
2. **硬门禁挂载**：`ctx.on('tools/pre-execute')` → 委托 Python 核心 `harness.core.cli decide`
   （与 opencode 时代 charter-gate 同源判定）：危险命令无备份、绕过唯一出口直连钉钉、
   未落闸写研发日志（含 bash 重定向）→ `{kind:'deny'}`
3. **看板自启**：启动 1.5s 后探测 8790 health，未运行则 spawn uvicorn
   （detached 常驻 + **PYTHONPATH 显式传宿主**，规避 DSH 进程内 spawn cwd 传递问题）
4. **宿主定位**：三要件（constitution + harness/workflow.yaml + docs/资源地图.md）——
   资源地图为宿主特有，避免把软链过 harness 组件的业务项目误判为宿主；向上/向下双向探测

## 四、踩坑记录

| # | 坑 | 根因 | 修复 |
|---|----|------|------|
| 1 | patch 子路径 `src/command` 找不到模块 | ESM import 无扩展名自动补全 | 子路径显式带 `.js` |
| 2 | decide 拦截时被误放行 | decide CLI 拦截退出码 1，execFileSync 抛异常 | 改用 spawnSync（解析 stdout JSON） |
| 3 | 看板自启 uvicorn ModuleNotFoundError | 宿主误判：业务项目（hetu-aether）软链过 harness 组件，被三要件前两条误判为宿主 | 三要件加 docs/资源地图.md；共享 lib.js 双向探测 |
| 4 | spawn cwd 传递异常 | DSH 进程内 spawn 的 cwd 不可靠 | spawn env 显式 PYTHONPATH=harn |
| 5 | `dsh` 命令不在 PATH | npx 安装环境 | 文档统一 `npx @deepseek-ai/dsh` 写法 |
