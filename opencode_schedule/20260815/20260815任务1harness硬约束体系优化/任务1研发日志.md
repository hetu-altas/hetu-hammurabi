# 任务1研发日志 · harness硬约束体系优化

## 一、任务概述

本任务为**机制自优化任务（meta task）**：针对 20260814 任务1（宪章体系 DSH 重构与运行看板）产出的
硬约束体系，对照 D1-D6 缺陷定义自检出 9 项可优化点（H1-H9，均在需求分析期逐条核实真实存在并附精确位置），

1. **规则外置（H1）**：判定规则从 `gate.py` 硬编码外置到 `harness/gate_rules.yaml`，改配置不重启即生效；

5. **脱敏回归（H5）**：旧版 `.opencode/plugin/charter-gate.ts` 的密钥脱敏能力迁移到 harness 体系；

7. **密钥管理（H7）**：密钥文件权限 600 强制 + `rotate-secret` 原子轮换子命令；
8. **日志误伤消除（H8）**：日志拦截增加放行名单（如「数据日志说明.md」正常文档不误拦）；
9. **并发安全（H9）**：seal-gate/re-seal 落盘加 flock 独占锁 + 落盘前重读校验。

**不动边界全程守住**：`constitution/**` 零改动、`.gate.json` v2 契约不变、`opencode_schedule/` 历史任务数据不动、
`.opencode/**` 旧配置不动（仅作只读迁移源）、`runlog/` 历史事件不动、`harness/core/notify.py` 不动。

## 四、核心设计

### 1. 规则外置 schema（H1）
- `gate_rules.yaml`（schema_version=1）承载全部判定规则与阈值，每段注释标注原硬编码位置（如 `freshness_seconds ← gate.py L35`）；
- 加载器按文件 **mtime（纳秒）** 检测变更，**改配置不重启即生效**；文件缺失 / YAML 解析失败 / schema 非法（缺字段、类型错、非法正则）→ **回退内置默认并告警（fail-closed）**，内置默认与默认文件行为一致（含绕过面完整规则，防规则文件损坏时绕过面退化）；
- 三处正则修正（对照任务书 4.1 缺陷）：① `rm_recursive` 前缀改 `(?:\brm|/bin/rm|\\rm)`（`\b` 前缀对 `/bin/rm`、`\rm` 无效）；② URL 拼接宽松模式 `[.\[\]'"+-]*`（原式无法跨 `."+"`）；③ yaml 双引号转义（`\\b`、`\\\\rm`）。

### 2. 绕过面样本清单（H2，全部拦截断言）
| 类别 | 样本 | 判定 |
|------|------|------|
| rm 变体 6 种 | `rm -rf` / `rm -fr` / `rm -r -f` / `rm --recursive --force` / `/bin/rm -rf` / `\rm -rf` | 全拦 |
| 销毁类 3 种 | `shred -u` / `unlink` / `rmdir -r` / `mv` → trash/回收站 | 全拦 |
| URL 混淆 2 种 | `oapi[.]dingtalk[.]com`（字符类点）、`"oapi."+"dingtalk.com"`（变量拼接） | 识别为通知外呼（须唯一出口） |
| 假备份 4 样本 | `rm -rf /data && echo backup`、`echo "backup" && rm -rf /data`、`rm -rf /data # 已备份 /backup/a` 等 | 拦截（剥离后无 backup） |
| 真备份 4 样本 | `cp -r /data /backup/data && rm -rf /data`、`rm -rf /data --backup=/backup/a`、`tar czf /backup/x.tgz /data && rm -rf /data` 等 | 放行 |
| 边界 | `echo "rm -rf /data"`（rm 写在 echo 文本中） | 销毁判定用原始 cmd → 仍拦 |

### 3. seal 双格式核对与汇总段修复（H3）
- **格式① unit_test 八格式**（`测试总数`/`成功`/`失败`/`错误` 四数字齐全才算命中，passed=成功数，失败+错误>0 拒绝）；
- **格式② unittest 原生格式**（`Ran N tests` + 末行 `OK`，FAILED 拒绝）；
- 双格式交叉核对不一致 → 拒绝（防伪造）；多 result 文件「任一拒绝即整体拒绝」；两个格式均无法解析 → fail-closed 拒绝落闸；
- **汇总段修复（测试节点首轮门禁失败 194/195 的根因）**：原生格式的 OK/FAILED 判定**仅限 "Ran N tests" 行之后的汇总段**——unittest -v 输出中反案例测试名可能含 "FAILED" 字样（如 `test_parse_native_format_failed`），全文搜索会把真实通过结果误判为失败；截取汇总段后正文不再影响判定，汇总段缺失/无法判定 → 拒绝（fail-closed）；
- 落闸数字 = 各文件解析值合计；真实样例验证：`test_harness_topology_result.txt` 同时含原生（Ran 20 tests）+ 八格式（20/20）→ 交叉核对一致通过；落闸走 `build_gate_v2`（契约零改动），落盘后 total/passed 与 result 一致，可被 gate_open 与 token 摘要复证。

### 4. re-seal 续签机制（H4）
- 语义：读现有 `.gate.json`（不存在/不可解析拒绝）；`schema_version==2` 且 run_id 一致（拒绝跨任务续签）；**重读 result 文件重新核对**（数字不符/文件缺失拒绝，防 result 被改后沿用旧闸）；构造新 gate **仅刷新 `updated_at` 并重算 `gate_token`**，run_id/task_dir/test_passed/total/passed/written_by/result_files 全部原样；flock 独占锁落盘；写 `event_type=re_seal` 审计事件（`runlog/events/YYYYMMDD/<run_id>.jsonl`，recorder schema）；
- 编排器 `reSeal()` 在 GATE_STALE 提示后自主执行；插件阻断消息附续签提示。

### 6. 密钥 600 与 rotate（H7）
- `secret.check_permission`：600 强制校验；`load_secret(enforce_600=True)`：权限非 600 自动修正后重读；
- `rotate_secret`：openssl rand -hex 32（回退 /dev/urandom 64 字节，同 install_dsh.sh）→ 原子写入（临时文件 + fsync + rename，防半写）→ chmod 600；轮换后旧闸 token（旧密钥 HMAC）自然失效；`--force` 语义正确；
- `install_dsh.sh`：密钥生成/已存在均强制 chmod 600（修正历史 777）；gate_rules.yaml 缺失时从默认模板生成（已存在不覆盖，保留用户配置）。

### 7. flock 并发（H9）
- `write_gate_locked(gate_file, gate_dict, expected_updated_at)`：`open(a+)` + `fcntl.flock(LOCK_EX)` → **锁内重读**（非法 JSON 拒绝「文件损坏」/ updated_at 与预期不符拒绝「已被并发更新，请重试」）→ truncate 写入 → 解锁；seal 与 re-seal 共用同一锁与比对逻辑（expected 为落盘前读取的现有 updated_at，首次落闸为 None）；
- 双进程实测（WSL 环境）串行化成功，`.gate.json` 内容完整合法（JSON + token 校验通过）；
- 平台注意：`fcntl` 仅 linux/unix；Windows 分支（msvcrt.locking）留注释不实现（当前无 Windows 运行需求）。
