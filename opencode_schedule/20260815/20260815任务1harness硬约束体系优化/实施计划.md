## 三、技术方案要点

### 3.0 编排者已确认决策（本任务契约，编码节点必须遵守）

1. **备份语义**：剥离 `echo`/`printf` 文本与注释（`#` 后）后再搜 `backup|备份`；销毁动作与备份声明须在同一条命令内
2. **result 双格式**：八格式优先、原生格式回退；多个 result 文件混合列表「任一拒绝即整体拒绝」
3. **re-seal**：由编排器自主执行（不依赖门禁插件）；rotate-secret 后旧闸 token 自然失效（HMAC 密钥更换）

### 3.1 A 阶段 · 规则外置（修复 H1/H8，依赖：无）

**gate_rules.yaml schema**（按任务书 4.1，补充实现细节）：

```yaml
schema_version: 1
freshness_seconds: 600
log_file:
  main_pattern: "研发日志"
  ext_pattern: "日志"
  allowlist: []            # A 阶段保持空（复现现状）；B 阶段打通后默认预置 "数据日志说明.md"
  task_dir_pattern: "opencode_schedule[/\\\\]\\d{8}[/\\\\][^/\\\\]+[/\\\\]"   # 原 L42，须外置
audit_files: ["研发流程状态.md"]
notify:
  url_patterns: [...]
  func_patterns: ["util_dingtalk", "send_markdown", "send_text", "HARNESS_NOTIFY", "harness\\.core\\.notify"]
  allow_patterns: ["HARNESS_NOTIFY", "harness\\.core\\.notify"]
dangerous_commands:
  rm_recursive: "(?:\\brm|/bin/rm|\\\\rm)\\s+(?:-[a-zA-Z]*r[a-zA-Z]*f|-r\\s+-f|--recursive\\s+--force|-fr|-rf)\\b"
  shred: "\\bshred\\b"
  unlink: "\\bunlink\\b"
  rmdir_recursive: "\\brmdir\\s+-[a-zA-Z]*r"
  mv_trash: "\\bmv\\b.*(?:回收站|trash)"
  drop_table: "\\bDROP\\s+(TABLE|STABLE)\\b"
  delete_from: "\\bDELETE\\s+FROM\\b"
  truncate: "\\bTRUNCATE\\b"
  drop_collection: "\\bdrop_collection\\b"
backup:
  pattern: "backup|备份"
  semantic: enforce
```

**关键实现点**：
- **加载器**（gate.py 内，约 120 行）：模块级缓存 `_rules_cache = (mtime, rules)`；每次判定调用前比对 `gate_rules.yaml` 的 mtime，变更即重载（「不重启即生效」）；YAML 解析失败 / schema 校验非法（缺必需字段/类型错）→ **回退内置默认值并告警**（fail-closed，默认值逐项对齐现 L35/L38-45/L49-74）
- **yaml 转正则**：rules 中模式字符串 `re.compile()` 预编译缓存；`backup.pattern` 转 `re.IGNORECASE`
- **默认回退可测性**：加载器暴露 `load_rules(rules_path=None)` 纯函数 + `get_effective_rules()` 供测试注入临时路径
- **A 阶段默认 allowlist 为空**（复现现状：`数据日志说明.md` 当前被拦）；H8 行为在 B 阶段通过「临时 rules 配置 allowlist」验证，E 阶段默认文件预置 `数据日志说明.md`（验收标准 8 以最终默认文件为准）
- **兼容性红线**：`is_log_file_write/is_notify_call/is_allowed_notify/is_destructive/has_backup_declaration/decide` 函数签名不变（现有 8 个测试文件直接调用，回归守护）；`gate_open` 的 `max_age_seconds` 参数保留（测试注入用），默认值取自 rules

### 3.2 B 阶段 · 绕过面收窄 + seal 可信度（修复 H2/H3，依赖 A）

#### 3.2.1 绕过面正则（对照任务书 4.1，修正三处正则缺陷——必须按此实现）

| 样本 | 任务书 4.1 原式问题 | 修正方案 |
|------|---------------------|---------|
| `rm -fr` / `rm -r -f` / `rm --recursive --force` / `/bin/rm -rf` / `\rm -rf` | `\b(?:rm\|/bin/rm\|\\rm)` 的 `\b` 前缀对 `/bin/rm`、`\rm` 不成立（`/`、`\` 为非单词字符，其前无单词边界） | `(?:\\brm\|/bin/rm\|\\\\rm)`——`\brm` 覆盖裸 rm；`/bin/rm`、`\\rm` 独立备选不带前缀边界 |
| `-fr` 变体 | `-[a-zA-Z]*r[a-zA-Z]*f[a-zA-Z]*` 不匹配 `-fr`（f 在 r 前） | 保留独立备选 `-fr`（任务书已含） |
| `oapi[.]dingtalk[.]com` 字符类 | `[.\\[\\]]` 字符类可匹配 `.`/`[`/`]`，OK | 保持 |
| `"oapi."+"dingtalk.com"` 变量拼接 | `oapi\s*[.\[\]]\s*dingtalk` 无法跨越 `."+"`（引号/加号不在字符类） | **新增宽松模式**：`oapi\s*[.\\[\\]'"+-]*\s*dingtalk\s*[.\\[\\]'"+-]*\s*com`（允许中间 0~N 个点/中括号/引号/加号/减号） |
| `rm -fr /data && echo backup` 假声明 | 原 `has_backup_declaration` 全文搜 backup | **备份语义校验**（见 3.2.2） |

**销毁命令清单**（rules 外置，含新增）：`rm_recursive`（rm 变体 5 种）/ `shred` / `unlink` / `rmdir_recursive` / `mv_trash`（回收站|trash）/ `drop_table` / `delete_from` / `truncate` / `drop_collection`（后四者保留现状语义）。

#### 3.2.2 备份语义校验（编排决策 1）

```
伪代码：
effective_cmd = cmd
  剔除 echo '...' / echo "..."/ printf '...' 的引号文本段（正则提取删除）
  剔除 # 到行尾的注释段
if is_destructive(effective_cmd):
    # 注意：销毁判定仍用原 cmd（不剥离），仅备份声明搜索用剥离后文本
    backup_found = backup_pattern.search(effective_cmd)
    if not backup_found: block(DATA_SAFETY)
```

- **销毁判定用原始 cmd**（防「把 rm 写进 echo 文本就绕过」——任意位置匹配语义不变）；**备份搜索用剥离后文本**
- 放行样例：`cp -r /data /backup/data && rm -rf /data`、`rm -rf /data --backup=/backup/a`、`tar czf /backup/x.tgz /data && rm -rf /data`
- 拦截样例：`rm -rf /data && echo backup`、`echo "backup" && rm -rf /data`、`rm -rf /data # 已备份 /backup/a`
- **注意与现有测试冲突**：`test_gate_bypass.py` L112 `"rm -rf /tmp/a # 已备份 /backup/a"` 与 L114 `"DELETE FROM users WHERE id=1 # 备份完成"` 在新语义下由「放行」变「拦截」→ **B 阶段同步调整这两条样例**（改为真备份动作），用例数不变（详见风险 R3）

#### 3.2.3 seal.py（新建，修复 H3/H9）

```
harness/core/seal.py
├── parse_unit_test_format(text) -> (total, passed) | None
│     正则 r"测试总数:\s*(\d+)" / r"成功:\s*(\d+)" / r"失败:\s*(\d+)" / r"错误:\s*(\d+)"
│     四数字齐全才算八格式命中；passed = 成功数；拒绝条件：失败+错误 > 0
├── parse_unittest_native_format(text) -> (total, passed) | None
│     r"Ran (\d+) tests" + 全文末段 "OK"（或 "FAILED (...)"）→ OK 时 passed=total；FAILED 拒绝
├── parse_result_file(path) -> (total, passed, format_name)
│     编排决策 2：先八格式、后原生；同一文件同时含两种格式且数字不一致 → 拒绝（交叉核对，fail-closed）
├── seal_gate(task_dir, run_id, result_files, secret, now=None) -> gate dict
│     1. 逐个解析 result 文件（任一无法解析 → 拒绝「result 文件格式无法识别」）
│     2. total=Σ或取八格式声明、passed=Σ成功；单文件多文件时 total=sum(total_i), passed=sum(passed_i)
│     3. 任一文件 失败+错误>0 或 FAILED → 拒绝「result 声明与文件内容不符」
│     4. build_gate_v2（契约不变）
│     5. flock 独占锁落盘 + 落盘前重读校验（见 3.4.2）
└── re_seal(task_dir, run_id, secret, runlog_root, project="", now=None) -> gate dict
      任务书 4.5 语义（见 3.4.1）
```

#### 3.4.1 re-seal 语义（任务书 4.5 + 编排决策 3）

```
re_seal(task_dir, run_id, secret, runlog_root, project):
  1. 读现有 .gate.json；不存在/不可解析 → 拒绝（无闸可续）
  2. schema_version==2 且 run_id 一致（否则拒绝，防跨任务续签）
  3. 重读 .gate.json 中 result_files 列表，逐个重新解析核对（编排决策 3：防 result 被改后沿用旧闸）
     - 解析结果与 gate.total/passed 不一致 → 拒绝
     - result 文件缺失 → 拒绝
  4. 构造新 gate：字段与现有一致（run_id/task_dir/test_passed/total/passed/written_by/result_files 全部原样），仅 updated_at=now 并重算 gate_token（写入方标记可附 re-seal 标注，不改变既有字段语义）
  5. flock 独占锁落盘（与 seal 同锁）
  6. recorder.record_event(event_type="re_seal", status="pass", detail={"refreshed": ...})
     —— recorder.py L37-40 VALID_EVENT_TYPES 必须增加 "re_seal"（清单外改动）
```

#### 3.4.2 并发落盘（修复 H9）

- `seal.py` 落盘统一走 `_write_gate_locked(gate, gate_file)`：
  ```
  with open(gate_file, "a+") as fh:
      fcntl.flock(fh, LOCK_EX)          # linux（本环境）
      fh.seek(0); existing = fh.read()  # 锁内重读
      if existing 非空且非合法 JSON → 拒绝「文件损坏」
      if existing.updated_at 与本次落盘前读取的不同 → 拒绝「已被并发更新，请重试」

  ```

## 七、给编码节点的关键提示

1. **顺序与门禁**：严格按 A→B→C→D→E 顺序；每阶段完成跑本阶段单测全绿再进下一阶段；E 阶段最后统一全量回归
2. **正则三处修正**（对照任务书 4.1 必须改）：① `rm_recursive` 前缀边界 `(?:\\brm|/bin/rm|\\\\rm)`（任务书原式 `\b` 前缀对 `/bin/rm`、`\rm` 无效）；② URL 拼接需新增宽松模式 `oapi\s*[.\\[\\]'"+-]*\s*dingtalk\s*[.\\[\\]'"+-]*\s*com`（任务书原式无法跨 `"+"`）；③ yaml 中转义：正则层 `\b` 在 yaml 双引号写 `\\b`，字面反斜杠 `\rm` 写 `\\\\rm`
3. **备份语义（决策 1）**：销毁判定用原始 cmd；备份搜索用剥离 echo/printf/注释后的文本；**必须同步调整 test_gate_bypass.py L112/L114 旧样例**（注释备份→真备份动作），否则 B 阶段回归必红
4. **seal 双格式（决策 2）**：八格式优先、原生回退；同一文件双格式交叉核对不一致→拒绝；多文件任一拒绝即整体拒绝；落闸数字=解析值（非命令行）
