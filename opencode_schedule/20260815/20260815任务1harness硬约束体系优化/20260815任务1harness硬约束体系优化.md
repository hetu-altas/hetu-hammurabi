### 目标

1. **规则外置（修复 H1）**：判定规则（危险命令/通知特征/日志模式/放行名单/新鲜度窗口）外置到 `harness/gate_rules.yaml`，支持模式与阈值配置，不编译即生效；gate.py 仅保留加载与执行逻辑
2. **绕过面收窄（修复 H2）**：rm 变体/销毁类命令全覆盖、通知 URL 混淆识别、备份声明语义校验（防假声明）
3. **落闸可信（修复 H3）**：seal-gate 解析 result 文件自动提取 total/passed 并核对，命令行不再接受数字
4. **续签机制（修复 H4）**：新增 re-seal（重新签名刷新 updated_at），门禁插件对 GATE_STALE 给出续签提示；续签行为写入 runlog 审计
5. **脱敏回归（修复 H5）**：将旧版脱敏能力迁移到 harness 体系（纯函数核心 + 插件钩子），含 chat 消息明文凭据扫描脱敏
6. **资产登记检查回归（修复 H6）**：在 harness 插件层恢复 `tool.execute.after` 资产登记一致性检查（软告警）
7. **密钥管理（修复 H7）**：密钥文件权限 600 强制 + 轮换子命令（rotate-secret），轮换后旧闸自然失效
8. **日志误伤消除（修复 H8）**：日志拦截增加放行名单（rules 外置），正常含「日志」文档不误拦
9. **并发安全（修复 H9）**：seal-gate/re-seal 落盘加文件锁（flock 独占）+ 落盘前重读校验

### 验收标准（可逐条验证）

1. **规则外置**：删除/修改 `gate_rules.yaml` 中任一模式后不重启即生效（单测验证加载逻辑 + 集成验证改配置即变判定结果）；非法规则文件加载时报错并 fail-closed
2. **绕过面全拦截**：以下样本逐条断言被拦——`rm -fr`、`rm -r -f`、`rm --recursive --force`、`/bin/rm -rf`、`\rm -rf`、`shred`、`unlink`、`rmdir -r`、`oapi[.]dingtalk[.]com`、`"oapi."+"dingtalk.com"` 变量拼接、`rm -rf /data && echo backup`（假声明）；合法备份声明（真备份动作 + backup 字样）放行
3. **seal-gate 自动核对**：构造 result 文件（八格式）与实际不符场景（如八格式声明 20 全过但文件含失败）→ 落闸拒绝并报原因；result 全过 → 自动提取数字落闸，`.gate.json` 的 total/passed 与 result 一致；命令行不再接受 `--total`/`--passed`；无法解析格式 → fail-closed
4. **10 分钟外不误拦**：落闸后模拟 11 分钟 → 日志写入被拦（GATE_STALE）→ 执行 re-seal → 同一操作放行；re-seal 不改 run_id/result_files/test_passed/total/passed，仅刷新 updated_at 并重签 token；re-seal 事件写入 runlog
5. **脱敏回归**：`sk-<16+位>`、`Bearer <token>`、`password=xxx`、`api_key: xxx` 等 ≥ 4 类样本在 chat 消息中被替换为 `[REDACTED]` 并告警；正常文本零误伤
6. **资产检查回归**：`write`/`edit` 目标位于 `docs/hetu-*/` 且未登记资源地图 → 软告警（不阻断）；已登记 → 无告警
7. **密钥管理**：install 脚本强制 `chmod 600 conf/gate_secret`（单测验证权限断言）；`rotate-secret` 后旧 token 校验失败、新 seal 生效
8. **日志误伤消除**：`数据日志说明.md`（任务目录内）不再被拦；`研发日志*.md` 仍拦；`研发流程状态.md` 仍放行
9. **并发安全**：两个进程并发 seal-gate 同一任务目录 → 串行化成功（或后写者报「已被并发更新，请重试」），`.gate.json` 内容完整合法
10. **回归**：现有测试全量不回归（106/106 baseline，见 `unit_test/test/test_harness_dsh_result.txt`），新增用例全过
11. **契约不变**：`.gate.json` v2 字段契约（schema_version=2 / run_id / gate_token HMAC / updated_at 入签名）、run_id 契约（任务目录名）不变；历史 `.gate.json` 仍可被 gate_open 正常校验（H2/H3/H4 改动不破坏既有判定）

### 4.1 `harness/gate_rules.yaml`（规则外置 schema，阶段 A）

schema_version: 1

log_file:
  main_pattern: "研发日志"        # 主模式（原 L38）

### 4.2 result 文件双格式（seal-gate 核对输入，阶段 B）

seal-gate 需自动解析 result 文件提取数字并核对，**兼容两种真实存在的格式**（已核实 `unit_test/test/` 下并存）：

| 格式 | 样例（真实） | 解析规则 |
|------|-------------|---------|
| ① unit_test 八格式（`constitution/unit_test/unit_test.md` L478-509 定义） | `unit_test/test/test_harness_topology_result.txt`：`测试总数: 20` / `成功: 20` / `失败: 0` / `错误: 0` | 正则提取四数字；核对：`total = 测试总数`、`passed = 成功`；拒绝条件：`失败+错误 > 0` 时声称全过 → 拒绝落闸 |
| ② unittest 原生汇总格式 | `unit_test/test/test_harness_dsh_result.txt`：`Ran 106 tests` + `OK`（或 `FAILED (failures=1)`） | 正则 `Ran (\d+) tests` + 末行 `OK`；核对：passed=total（OK 时），FAILED 时拒绝 |

> 核对规则（fail-closed）：两个格式均无法解析 → 拒绝落闸并报「result 文件格式无法识别」；解析出的数字与声称不一致 → 拒绝；混合文件列表按「任一拒绝即拒绝」。落闸后 `.gate.json` 的 total/passed 以解析值为准（与 result 一致，可被 gate_open 的 R3 与 token 摘要校验复证）。

### 4.3 CLI 接口变更（阶段 B/D）

```bash
# 原（删除 --total/--passed，H3）：
python -m harness.core.cli seal-gate --task-dir <任务目录> --run-id <任务目录名> \
    --results <result 文件...> --total N --passed N --secret-file <密钥文件>
# 新：自动解析核对
python -m harness.core.cli seal-gate --task-dir <任务目录> --run-id <任务目录名> \
    --results <result 文件...> --secret-file <密钥文件> [--json]

# 新增 re-seal（H4）：刷新 updated_at 并重签 token，其余字段不变，写 runlog audit 事件
python -m harness.core.cli re-seal --task-dir <任务目录> --run-id <任务目录名> \
    --secret-file <密钥文件> [--runlog <runlog 根>] [--json]

# 新增 rotate-secret（H7）：轮换密钥（旧闸 token 即失效）
python -m harness.core.cli rotate-secret --secret-file <密钥文件> [--force]
```

### 4.4 `.gate.json` v2 契约（**不变**，仅声明）

`schema_version=2` / `run_id` / `task_dir` / `test_passed` / `total` / `passed` / `written_by` / `result_files` / `gate_token`（HMAC-SHA256，payload 含 run_id + 结果摘要 + 声明字段含 updated_at）/ `updated_at`。gate_open 判定链（GATE_MISSING → SCHEMA → RUN_ID_MISMATCH → NOT_PASSED → NO_RESULTS → TOKEN_INVALID → STALE）与 R1（updated_at 入签名）/R2（未来时间戳拒绝）/R3（空 result_files 拒绝）语义全部保留。

### 4.5 续签机制语义（H4，阶段 D）

- re-seal 仅允许更新 `updated_at`（刷新为当前时间）并重算 `gate_token`；`run_id`/`result_files`/`total`/`passed`/`test_passed` 必须与现有 `.gate.json` 一致，不一致拒绝（防续签篡改）
- re-seal 前重读 result 文件并重新核对（防止 result 被改后沿用旧闸）
- 每次 re-seal 写一条 `event_type=re_seal` 审计事件到 `runlog/events/YYYYMMDD/<run_id>.jsonl`（复用 recorder schema）
- 门禁插件判定命中 `GATE_STALE` 时，reason 附「提示：可执行 re-seal 续签（由编排器执行）」
