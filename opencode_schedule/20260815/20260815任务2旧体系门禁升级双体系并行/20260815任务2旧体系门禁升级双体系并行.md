## 四、接口 / 数据格式定义

### 4.1 CLI 调用契约（旧插件调用格式，已核实 `harness/core/cli.py`）

```bash
# ① 门禁判定（tool.execute.before 委托）：
python -m harness.core.cli decide \
    --task-dir <任务目录绝对路径> --run-id <任务目录名> \
    --file <目标文件路径或空串> --cmd <bash 命令或空串> \
    --secret-file <HARNESS_DIR>/conf/gate_secret --json
# 退出码：0=放行，1=拦截；stdout JSON：{"blocked": bool, "code": str, "reason": str, "event_type": str}

# ② 脱敏（chat.message 委托）：
python -m harness.core.cli redact --text <消息文本> --json
# stdout JSON：{"text": str(已脱敏), "hits": int}

# ③ 资产登记检查（tool.execute.after 委托）：
python -m harness.core.cli assets-check --project-dir <业务项目目录> --file <目标文件> --json
# stdout JSON：{"ok": bool, "reason": str, "map_path": str}
```

> 注意：`decide` 的 `--secret-file` 为 **required**（cli.py L264），旧插件必须拼接 `<HARNESS_DIR>/conf/gate_secret` 传入（参照 `harness/plugins/charter-gate.ts` L53）；`--task-dir`/`--run-id` 亦 required。

### 4.2 运行环境解析（旧插件新增能力，参照 DSH 插件 `harness/plugins/charter-gate.ts` L34-49 `resolveEnv`）

- 读取 `<业务项目>/.opencode/.harness-env` 的 `VENV_BIN`/`HARNESS_DIR` 字段（K=V 逐行解析，兼容引号包裹）；
- `.harness-env` 缺失或字段缺失时回退：`VENV_BIN` → `python3`；`HARNESS_DIR` → 同父目录下同时含 `constitution/constitution.md` + `.opencode/agents/` + `docs/资源地图.md` 的 hetu-* 目录（宿主查找）→ 仍无则当前项目自身；
- 子进程执行：`cwd = HARNESS_DIR`（保证 `-m harness.core.cli` 模块可导入，参照 DSH 插件 L64-68）；
- 注意宿主自身（hetu-hammurabi）无 `.harness-env`，回退宿主查找须命中自身（本任务验收冒烟项①即此场景）。

### 4.3 旧插件改造后的钩子行为（方案1）

| 钩子 | 触发工具 | 委托命令 | 阻断/告警行为 |
|------|---------|---------|--------------|
| `tool.execute.before` | write / edit / apply_patch / bash | decide | `blocked=true` → `throw new Error("[charter-gate] " + reason)`（含 code 与 GATE_STALE 续签提示，参照 DSH 插件 L120-128）；其余放行 |
| `chat.message` | — | redact | `hits>0` → 逐 text part 替换为返回的 text，`client.app.log` warn 告警（含 sessionID） |
| `tool.execute.after` | write / edit 且目标在 `docs/hetu-*/` | assets-check | `ok=false` → warn 软告警（不阻断） |

### 4.4 注释与形态约定

- 保持 `export default CharterGate`（opencode Plugin 形态，`client`/`directory` 参数签名不变，参照现 L98-102）；
