## 四、核心设计

### 1. resolveEnv：宿主回退与宿主自身场景
- 解析 `<业务项目>/.opencode/.harness-env` 取 `HARNESS_DIR`/`VENV_BIN`：K=V 逐行解析，跳过空行与 `#` 注释，`/^"|"$/g` 剥离引号包裹的值（路径含空格场景）；
- **回退链**：`VENV_BIN` 缺失 → `python3`；`HARNESS_DIR` 缺失 → `findHostDir` 三要件宿主查找（同父目录下同时含 `constitution/constitution.md` + `.opencode/agents/` + `docs/资源地图.md` 的 `hetu-*` 目录，排序后遍历）→ 仍无命中返回当前项目自身；
- **宿主自身场景**（hetu-hammurabi 无 `.harness-env`）：宿主查找按三要件命中自身（hetu-hammurabi 三要件齐全，同父目录其余 hetu-* 无 constitution），本任务冒烟①即此场景——resolveEnv 正确解析出宿主自身，decide 判定 GATE_MISSING 拦截写日志；
- 子进程执行 `cwd = HARNESS_DIR`（保证 `-m harness.core.cli` 模块可导入，参照 DSH 插件 L64-68）；`execFileSync` 数组传参（无 shell 注入面）、stdin 忽略。

### 2. resolveTaskContext：任务上下文推导（与 DSH 侧的机制差异）
- opencode 运行时**无任务注入**（DSH 侧由 dsh-agent 注入 taskDir/runId），故从工具参数（filePath/cmd）按 `opencode_schedule/<YYYYMMDD>/<任务目录>` 路径模式正则推导 `{ taskDir, runId }`（正则 `opencode_schedule[/\\]\d{8}[/\\][^/\\\s]+`，兼容反斜杠路径，runId 取最后一段）；
- **推导不到时 fail-closed**：`task_dir` = 项目目录、`run_id` = ""——命中日志/通知判定时因 run_id 不匹配被核心拦截（gate.py gate_open 校验链 fail-closed），非日志路径由核心第 4 分支直接放行（不放大拦截面）。

### 3. 三钩子委托与 fail-closed 兜底
| 钩子 | 触发工具 | 委托 | 行为 |
|------|---------|------|------|
| `tool.execute.before` | write / edit / apply_patch / bash | decide | `blocked=true` → warn 告警 + `throw new Error("[charter-gate] " + reason)` 硬阻断；reason 含 `GATE_STALE` 时附「可执行 re-seal 续签」提示（与 DSH L120-128 一致）；**判定子进程真异常（stdout 非 JSON/启动失败）→ error 告警 + fail-closed 拦截（宁拦勿放，不 fail-open）** |
| `chat.message` | — | redact | `hits>0` → 逐 text part 替换为返回文本 + warn 告警（含 sessionID）；子进程失败 → 返回原文 + error 告警「未脱敏原文输出（风险提示）」，不拦会话（chat.message 无阻断语义） |
| `tool.execute.after` | write / edit 且目标匹配 `docs[/\\]hetu-[^/\\]+[/\\]` | assets-check | `ok=false` → warn 软告警（不阻断）；检查失败按未登记软告警 |

- **decide 委托增强（评审 3.1 认可）**：blocked=true 时 CLI 以退出码 1 结束，`execFileSync` 抛错但 **stdout 仍含判定 JSON**——从 `err.stdout` 兜底解析并返回，保证 reason/code 完整透传（GATE_STALE 续签提示依赖此）；stdout 非 JSON → fail-closed 抛错。
