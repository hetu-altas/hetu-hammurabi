## 三、技术方案要点

### 3.1 旧插件薄适配改造设计（核心）

#### 3.1.1 `resolveEnv`（替代原 `resolveResourceMapPath` L56-78）

- **.harness-env 解析**：读取 `<projectDir>/.opencode/.harness-env`，K=V 逐行解析（跳过空行与 `#` 注释、剥离双引号包裹值——兼容路径含空格），取 `HARNESS_DIR` / `VENV_BIN` 字段；参照 DSH 插件 `harness/plugins/charter-gate.ts` L34-49 `resolveEnv`。
- **宿主自身无 .harness-env 回退**（本任务关键场景，验收冒烟项①即是）：
  - `VENV_BIN` 缺失 → 回退 `python3`；
  - `HARNESS_DIR` 缺失 → 同父目录（`path.dirname(projectDir)`）下遍历 `hetu-*` 目录，命中同时含 `constitution/constitution.md` + `.opencode/agents/` + `docs/资源地图.md` 三要件的目录为宿主（参照 topology.md L55 回退规则①与 `assets_check.py` L31-64 三级回退思路）；**宿主自身即满足三要件 → 回退命中自身**（hetu-hammurabi 场景）；仍无 → 当前项目自身。
- 返回值：`{ HARNESS_DIR, VENV_BIN, PROJECT_DIR }`（三字段齐备后供三个委托函数使用）。

#### 3.1.2 三个钩子的委托实现

统一调用范式（与 DSH 插件完全同构）：

```ts
const out = execFileSync(python, args, {
  cwd: env.HARNESS_DIR,          // 保证 `-m harness.core.cli` 模块可导入（参照 DSH L64-68）
  encoding: "utf-8",
  stdio: ["ignore", "pipe", "pipe"],
}).trim();
return JSON.parse(out);
```

| 钩子 | 委托命令（参数契约见 cli.py） | 阻断/告警行为 |
|------|------------------------------|--------------|
| `tool.execute.before`（write/edit/apply_patch/bash） | `decide --task-dir <任务目录> --run-id <任务目录名> --file <路径或空串> --cmd <命令或空串> --secret-file <HARNESS_DIR>/conf/gate_secret --json`（cli.py L259-266，`--secret-file` required L264） | `blocked=true` → `throw new Error("[charter-gate] " + reason)`；reason 含 `GATE_STALE` 时附「可执行 re-seal 续签」提示（参照 DSH L120-128）；其余放行 |
| `chat.message` | `redact --text <消息文本> --json`（cli.py L304-307） | `hits>0` → 逐 text part 替换为返回的 text，`client.app.log` warn 告警（含 sessionID，参照 DSH L134-149） |
| `tool.execute.after`（write/edit 且目标在 `docs/hetu-*/`） | `assets-check --project-dir <projectDir> --file <目标文件> --json`（cli.py L309-313） | `ok=false` → warn 软告警（不阻断，参照 DSH L153-162） |

**异常兜底（fail-closed 决策）**：

| 场景 | 处理 |
|------|------|
| `decide` 子进程失败（非零退出/JSON 解析失败） | **fail-closed**：按 `blocked=true` 抛错拦截 + error 日志（宁拦勿放，安全攸关操作） |
| `redact` 子进程失败 | 返回原文 + error 告警「未能脱敏」（chat.message 无阻断语义，不应拦会话，但必须告警标注风险） |
| `assets-check` 子进程失败 | 按 `ok=false` 处理 warn 告警（软告警本就只提醒） |

## 五、风险与注意事项

| # | 风险 | 说明 | 缓解 |
|---|------|------|------|
| 1 | **Node v18.19.1 TS 无法自动单测**（已实测：`--experimental-strip-types` bad option 需 Node ≥22.6；`--check` 无法解析 TS 类型语法） | TS 适配层无自动单测覆盖 | ① Python 侧 CLI 契约测试覆盖旧插件全部调用路径入参出参；② 与 DSH 同构 TS 逐段比对（见 3.1.3 清单）；③ 改后**重启 opencode 验证插件加载日志**（`charter-gate plugin initialized`）；④ 不引入新依赖（`.opencode/node_modules` 仅 @opencode-ai/plugin） |
| 2 | **CLI 子进程开销** | 每次写入类工具调用额外起 1 个 Python 子进程（约百毫秒级），且 `--cmd`/`--file` 参数含特殊字符 | 用 `execFileSync` 数组参数传参（无 shell 注入面）；子进程开销可接受（门禁判定本就是低频操作）；decide 失败 fail-closed 拦截并 error 告警 |
| 3 | **宿主自身 env 回退** | hetu-hammurabi 无 `.opencode/.harness-env`，回退须命中自身（三要件齐全）；若回退逻辑漏自身或误判其他 hetu-* 项目 → cwd 错误导致 CLI 无法导入 | 回退实现严格按 3.1.1：遍历同父目录 hetu-* 取三要件齐全者，宿主自身在三要件齐全时**必须**命中；冒烟①即此场景实测 |
| 4 | **插件加载失败影响 opencode 启动** | 语法错误/块注释 `*/` 截断 → 插件静默加载失败，门禁全部失效（fail-open 意外放行） | 块注释严禁 `*/` 序列；与 DSH 同构逐段比对；重启后查 `client.app.log` 的 initialized 日志与配置加载 |
| 5 | **冒烟④新鲜度窗口** | 任务1 落闸时间可能已超 10 分钟（gate_rules.yaml freshness_seconds）→ 合法闸也会 GATE_STALE | 冒烟④前先对任务1 目录执行 `re-seal` 续签（cli.py L148-175），再 decide 验证 blocked=false；并如实记录续签动作 |
| 6 | **decide `--secret-file` required** | 旧插件必须拼接 `<HARNESS_DIR>/conf/gate_secret`，漏传 → CLI 报错（argparse required）→ 触发 fail-closed 拦截一切写入 | 委托实现强制拼接（参照 DSH L53）；conf/gate_secret 已实测存在（65 字节） |
