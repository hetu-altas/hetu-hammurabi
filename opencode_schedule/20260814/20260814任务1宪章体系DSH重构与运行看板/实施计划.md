## 三、技术方案要点

### 3.1 门禁信任模型（D1/D2）

- 判定入口：`gate.decide(file_path, cmd, task_dir, run_id, secret)`，纯函数、fail-closed
- D1：`find_gate_file` 只查任务目录自身；`gate_open` 校验 `run_id` 与任务目录名一致
- D2：`build_gate_v2` 由编排器调用（tester 只写 result）；`gate_token = HMAC(run_id + 结果摘要 + 关键声明字段)`，篡改任何字段即失效；10 分钟新鲜度窗口

### 3.2 绕过面覆盖（D4）

- 通知：URL 特征（oapi.dingtalk.com/robot/send）+ 函数特征（util_dingtalk/send_*）+ 出口标记（HARNESS_NOTIFY/harness.core.notify）；唯一出口 `notify.py` 包装 hetu-aether util_dingtalk
- 危险命令：任意位置正则（rm -rf/DROP/DELETE FROM/TRUNCATE/drop_collection），需显式 backup/备份
- 日志识别：审计文件放行（研发流程状态.md），主模式 + 任务目录内变体模式

### 3.3 流程定义外置（D5）

`harness/workflow.yaml`：节点 -1~7、gate 挂载、retry（3/2 轮）、requires 依赖；
`workflow.py` 提供 load/validate/next_allowed；TS 编排插件按此推进。

### 3.4 运行度量（D6）

- 事件流：`run_event` JSONL，按日分目录、按 run_id 分文件，追加写、线程安全
- 聚合：stats.py 定义口径（成功率含重试轮、拦截率=拦截/检查）；history.py 静态解析存量任务（source=history）
- API：FastAPI 5 端点 + 静态前端挂载；看板展示总览/节点/门禁/任务/详情

### 3.5 DSH 适配（阶段B）

- profile：package.json + dsh.profile（bundles 顺序）+ cordis.patch.yml（渲染 HARNESS_DIR 占位）
- 插件：3 个 cordis 风格 TS 插件（gate/recorder/orchestrator），逻辑薄适配到 Python 核心
- agents/skills：从 .opencode/ 迁移并改写（tester 写/验分离、notifier 唯一出口、回退规则兼容新旧布局）
