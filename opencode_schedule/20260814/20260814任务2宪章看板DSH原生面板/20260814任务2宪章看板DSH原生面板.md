## 一、任务要求

### 需求背景

当前看板挂接方案（任务1 交付）为 **webserver 前缀路由代理**：`/dashboard` 由 `harness/dsh/plugins/dashboard-proxy.ts` 代理到独立 FastAPI 服务（8790）。已验证可用，但存在局限：

| 局限 | 说明 |
|------|------|
| L1 双进程 | 看板服务（8790）需独立维护/自启，GUI 与看板生命周期分离 |
| L2 非原生体验 | 面板是独立 HTML 页面，未融入 GUI 主题/导航/侧边栏；刷新与路由跳转割裂 |
| L3 无面板开发链 | 无法利用 DSH 的 client-plugin HMR（`pnpm run dev:web` 热更新）做面板开发 |
| L4 数据多一跳 | 浏览器 → 3080 代理 → 8790 直连，链路多一跳 |

DSH 原生扩展机制（已侦察确认）：
- **client-plugin 双面结构**：node 半区 = 普通 cordis 插件（主入口 `lib/index.js`，可注册 webserver 路由/提供服务）；browser 半区 = `window.__ModuleLoader__.load({id, factory})` 包装的 React 模块（`exports["./client"]` → `lib/client.js`），由 **apps/web 的 Vite 构建**生成
- **注册元数据**：package.json 的 `dsh.client` 字段（`inject` 依赖列表 + `platform: "web"`）；profile patch 的 `insert` 行挂载（与任务1 代理插件同机制）
- **UI 插槽**：`@deepseek-ai/dsh-client-ui-slots`（SlotMap 注册 API）+ `dsh-client-ui-layout`（布局插槽），面板挂载点实现期从源码确认
- **主题**：`@deepseek-ai/dsh-client-ui-primitives` + CSS 变量（`--dsw-*`），面板可完全融入 GUI 视觉

### 目标

1. 交付 **hetu-dashboard client-plugin 包**：原生面板嵌入 DSH web GUI（侧边栏入口 + 独立视图），展示任务1 看板全部内容（总览/节点统计/门禁拦截/任务列表/任务详情）
2. 数据走 **同源代理**：browser 半区 fetch `/api/hetu-dashboard/*`，node 半区注册 webserver 路由转发到看板数据源（8790 或内嵌聚合），消除跨域与直连依赖
3. 建立 **DSH 源码构建链**：克隆 deepseek-harness → `pnpm install` → `pnpm run dev:web`（HMR 面板开发）→ `pnpm run build`（产物）
4. 保留代理路径 `/dashboard` 为降级方案，原生面板为主入口
5. 原看板服务（8790）**不删除**：作为数据源与降级通道继续运行

### 验收标准（可逐条验证）

1. **原生入口**：`dsh web` 启动后 GUI 内出现「宪章看板」入口（侧边栏图标/视图项），点击进入原生面板，URL 为 GUI 内路由（非 `/dashboard` 代理页）
2. **面板功能**：面板包含——总览 4 卡片（任务数/节点运行次数/成功率/门禁拦截率）、节点统计表（含成功率条/平均轮次）、门禁拦截列表、任务列表（点击行展开详情：节点时间线 + 事件流），与任务1 看板数据一致
3. **同源数据**：面板所有请求走 `/api/hetu-dashboard/*`（经 node 半区转发），无跨域错误；8790 停止时面板显示友好降级提示（数据不可用态）
4. **主题融入**：面板使用 `--dsw-*` 主题变量与 GUI 组件原语，明暗主题下可读
5. **HMR**：`pnpm run dev:web` 运行中修改面板源码，GUI 内热更新无需手动刷新（client-plugin HMR 链验证）
6. **构建产物**：`pnpm run build` 产出含 `hetu-dashboard` client.js 的 dist，重启后正常加载
7. **降级共存**：`/dashboard` 代理路径仍可用（代理插件未卸载）
8. **单测**：node 半区路由/转发/错误处理有单测；数据契约与 `harness/core/stats.py` 输出对齐（schema 断言）
9. **资产沉淀**：client-plugin 开发指南文档 + dashboard.md 更新 + 资源地图登记

## 四、接口 / 数据格式定义

### 4.1 client-plugin 包契约（双面结构）

```jsonc
// package.json（关键字段）
{
  "name": "@deepseek-ai/hetu-dashboard",        // 或本地作用域名（实现期定）
  "type": "module",
  "main": "lib/index.js",                        // node 半区（构建后）
  "exports": {
    ".": { "default": "./lib/index.js" },
    "./client": { "default": "./lib/client.js" } // browser 半区（Vite 构建产物）
  },
  "dsh": {
    "client": {
      "inject": [
        "@deepseek-ai/dsh-client-runtime",
        "@deepseek-ai/dsh-client-ui-layout",
        "@deepseek-ai/dsh-client-ui-slots"
      ],
      "platform": "web"
    }
  }
}
```

- node 半区：`export const name/inject/apply`，`apply(ctx)` 中 `ctx.webServer.register({kind: "prefix", path: "/api/hetu-dashboard", handler})`（复用任务1 代理插件已验证的注册 API）
- browser 半区：**源码用 React + ui-slots 写**，`client.js` 由 apps/web Vite 构建生成（`__ModuleLoader__.load` 包装 + CSS 虚拟模块注入，见 `dsh-client-ui-sidebar` 产物形态）；**禁止手写构建产物**
- 插槽挂载点：实现期从 `dsh-client-ui-layout` / `dsh-client-ui-slots` 源码确认（侧边栏注册 API 或视图路由注册），骨架阶段先以最小可显示面板打通

### 4.2 数据接口（同源代理，与任务1 看板 API 对齐）

| 前端路径（browser 半区 fetch） | 后端真实路径 | 说明 |
|------|------|------|
| `GET /api/hetu-dashboard/health` | 8790 `/api/health` | 健康探测（面板降级态依据） |
| `GET /api/hetu-dashboard/stats/overview?period=...` | `/api/stats/overview` | 总览 |
| `GET /api/hetu-dashboard/stats/nodes?period=...` | `/api/stats/nodes` | 节点统计 |
| `GET /api/hetu-dashboard/stats/gates?period=...` | `/api/stats/gates` | 门禁拦截 |
| `GET /api/hetu-dashboard/tasks?period=...` | `/api/tasks` | 任务列表 |
| `GET /api/hetu-dashboard/tasks/{run_id}` | `/api/tasks/{run_id}` | 任务详情 |

转发规则：路径去掉 `/api/hetu-dashboard` 前缀后转发到 `127.0.0.1:8790`（保留 query）；8790 不可达时返回 `{"ok": false, "reason": "dashboard service unavailable"}` + 面板显示降级态（不返回 502 HTML，方便前端统一处理）。

### 4.3 数据契约（前端类型与 stats.py 对齐）

面板 `api.ts` 的类型定义必须与 `harness/core/stats.py` 输出结构一致（overview/nodes/gates/tasks/task-detail 五组），并在单测中用真实 stats 输出做 **schema 断言**（防止前后端口径漂移）：

```ts
interface Overview {
  total_tasks: number; total_node_runs: number;
  success_rate: number; gate_block_rate: number;
  gate_block_count: number; gate_pass_count: number;
  period: string; period_start: string; period_end: string;
}
// nodes: {node, node_name, runs, success, fail, success_rate, avg_round}[]
// gates: {rate, count, pass_count, events: GateEvent[]}
// tasks: {run_id, project, date, status, node_count, last_ts, source}[]
// taskDetail: {run_id, project, source, timeline, events, files}
```
