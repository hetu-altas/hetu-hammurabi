## 三、核心设计

1. **双面插件**：node 半区（cordis 插件，可注册 webserver 路由）+ browser 半区（`window.__ModuleLoader__.load({id, factory})` 包装的 React 模块），`package.json` 的 `dsh.client` 元数据声明 browser 半区依赖与平台
2. **插槽挂载**：`sidebar.footer.action`（list 型，侧边栏底部按钮）+ `shell.overlay`（list 型，全屏浮层）——两个 additive 挂载点，不替换现有 UI；注册形态 `ctx.slots.inject(slot, () => ctx.slots.register({name, id, label}, Component))`
3. **数据通道**：browser 半区 fetch `/api/hetu-dashboard/api/*` → dashboard-proxy 剥前缀 → 8790 `/api/*`；上游不可达返回 `{"ok":false}`（200）统一降级
4. **主题融入**：CSS 注入（`data-plugin-css` style 标签）+ `--dsw-*` 主题变量，明暗主题自适应

## 四、踩坑记录（loader 解析规则）

**问题**：patch insert 行的 `name: "@hetu/dsh-dashboard-panel"`（包名）注册后，插件 apply 未执行、client bundle 未 serve（`/plugins/<id>/client.js` 404、boot manifest 无条目）；而绝对路径 .ts 插件（dashboard-proxy）正常。

**定位**：cordis-plugin-loader 的 `import(name)` 对包名直接 `import(name)`——解析上下文是 **dsh 安装目录**（`~/.npm/_npx/<hash>/node_modules`），**不查 profile 的 node_modules**（profile 内 `npm install` 的包 loader 找不到）。

**修复**：包装入安装目录 node_modules → 包名可解析 → apply 执行、modules 插件 serve client.js、boot manifest 注入。

**验证命令**（写进 dsh-client-plugin.md）：`dsh --profile web --dump-config | grep hetu`（配置树）、
`curl /plugins/@hetu/dsh-dashboard-panel/client.js`（bundle serve）、
`curl / | grep __DSH_BOOT__ | grep -c hetu`（manifest 注入）。
