# 任务拆分评估规范

> 通用规范。用于任务书编写前评估：以当前模型上下文窗口为约束，判断单任务是否适合单 session 跑完整研发流程，以及需要拆分到多细的粒度。
> 相关实现：`../hetu-hammurabi/.opencode/`、`../hetu-hammurabi/templates/task_book.md`。

## 一、上下文预算模型

一次完整研发流程的上下文消耗分为两部分：

| 组成部分 | 构成 | 占比估算 |
|---------|------|---------|
| **主会话累计**（编排器） | 任务书 + 实施计划 + 各节点返回摘要 + 流程状态 | 任务材料总量的 20-30% |
| **单节点峰值**（编码/评审/单测） | 任务书 + 实施计划 + 参考代码 + 宪章 + 改动文件 | 通常为最紧约束，占材料总量 60-80% |

### 预算规则（硬约束）

1. **单节点峰值 ≤ 模型窗口的 60%**：超出后模型注意力显著下降、易丢失细节
2. **主会话累计 ≤ 模型窗口的 30%**：防止中途触发压缩导致关键信息丢失
3. **任务材料总量**（任务书+计划+参考+实现+测试+评审素材）**≤ 窗口的 80%**：单节点与主会话的上限由总量推导

### 估算基准（中文代码场景）

| 材料 | 估算 |
|------|------|
| 1 行 Python 代码（含中文注释） | 8-15 tokens |
| 1000 中文字符 | 约 800 tokens |
| 单接口文档（tushare 单接口） | 1-3K tokens |
| 单专题 DDL 文件 | 5-15K tokens |
| 参考代码模块（500 行） | 5-8K tokens |

## 二、主流模型上下文分级

| 级别 | 窗口 | 代表模型 |
|------|------|---------|
| S 级 | 10M | Llama 4 Scout |
| A 级 | ~1M | Gemini 3.1 Pro、Claude Opus 4.8/4.7/4.6、Claude Sonnet 4.6、GPT-5.5/5.4、DeepSeek V4 Pro/Flash、MiniMax M3、Qwen3.5-Plus |
| B 级 | ~400K | GPT-5.4-mini、GPT-5.2-Codex |
| C 级 | ~200K | Claude Haiku 4.5、GLM-5.2/5.1/5、Kimi K2.6、DeepSeek V3.2 |

## 三、任务粒度分级（以 A 级为基准）

| 级别 | 新代码量 | 涉及文件 | 参考阅读量 | 单 session 判定 |
|------|---------|---------|-----------|----------------|
| 小 | ≤ 300 行 | ≤ 2 | ≤ 30K | 任意级别模型均可 |
| 中 | 300-1500 行 | 2-5 | ≤ 80K | A/B 级单 session 安全；C 级需压缩参考阅读 |
| 大 | 1500-4000 行 | 5-10 | ≤ 200K | 仅 A 级可单 session；建议拆 2-3 个中任务 |
| 超大 | > 4000 行 | > 10 | > 200K | **必须拆分** |

C 级模型（~200K 窗口）阈值减半：中任务上限约 700 行，大任务上限约 1500 行。

## 四、拆分原则

1. **以"可独立验证闭环"为单位**：每个子任务都能独立完成 编码 → 单测(门禁) → 评审，不允许拆出"只写代码不测试"的悬空单元
2. **按依赖顺序拆分**：基础工具/公共方法 → 主流程 → 脚本/配置 → 文档沉淀
3. **接口即契约**：子任务间以函数签名、表结构、文档路径为边界，上游未合并不阻塞下游按契约开发
4. **单子任务 ≤ 大任务级别**：拆分结果中任一子任务仍超限则继续拆

## 五、评估流程（写任务书前执行）

1. 列出任务书「文件与目录」清单，估算改动行数合计
2. 估算必要参考阅读量（接口文档/DDL/参考代码，可查资源地图）
3. 按第二节定位当前模型级别，查第三节判定任务级别
4. 超限 → 按第四节原则拆分为多个任务书，按序编号（任务1/任务2/...），每个仍走完整流程

## 六、示例

| 任务 | 材料量估算 | 判定 |
|------|-----------|------|
| 单工具方法（如 util_milvus.recall，~120 行+测试） | 总量 ~60K | 小任务，任意模型单 session |
| 单数据源管道（major_news，4 文件 ~800 行） | 总量 ~150K | 中任务，A 级安全 |
| 多数据源定时向量化泛化改造（>10 文件，重构既有代码） | 总量 > 400K | 超大任务，必须按数据源拆 2-3 个 |
