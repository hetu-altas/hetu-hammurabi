# 引擎性能对比报告：DSH vs opencode 宪章流程耗时

> 20260815 登记。对比河图体系宪章编程流程在 **DSH（/cc 命令）** 与 **opencode（/dev 命令）**。
> 注：20260815 任务3 起 opencode 命令已同步更名 /cc；本文 /dev 为历史执行引擎标注（历史任务确由 /dev 执行），统计口径不变。
> 两种执行引擎下的任务耗时。数据来自看板运行事件库（runlog，秒级）与各任务
> `研发流程状态.md` 时间列（分钟级）；统计逻辑固化于 `harness/core/stats.py#engine_benchmark`，
> 看板 API `GET /api/stats/benchmark` 实时输出。

## 一、结论

**同等规模的宪章流程任务，DSH 平均耗时约 35 分钟，opencode 约 52 分钟——DSH 快约 32%**
（中位数快约 39%）。差距主要来自流程启动、节点切换与工具调用的效率。

| 指标 | DSH（20260815 起 /cc） | opencode（历史 /dev） | 差距 |
|------|----------------------|----------------------|------|
| 平均总耗时 | **35.4 分钟** | **51.9 分钟** | 快 **32%** |
| 中位数耗时 | **32.5 分钟** | **53.5 分钟** | 快 **39%** |
| 可算样本 | 8 个任务 | 8 个任务 | — |

## 三、统计口径与剔除规则

1. **任务耗时定义**：
   - runlog 事件任务：节点 -1/0 `node_start` → 首次节点 7 `node_end` 的时间差（秒级）
   - 状态文件任务：首行时间 → 末行时间（分钟级）
2. **引擎归属**：`run_id` 以 `20260815` 开头 → DSH（/cc 全面启用日）；否则 opencode
3. **剔除**（固化在 benchmark 逻辑，看板展示剔除项）：
   - 跨天异常（>1000 分钟）：`20260809任务1量化投研架构设计`（5205 分，状态文件跨多天，非单次执行）
   - 人工执行：`20260814任务1/2`（runlog 记录窗口不代表真实执行时长）
4. **不可算样本**：状态文件时间列仅日期（无时分）的任务（DSH 4 个 / opencode 8 个）不计入

## 四、局限与说明（诚实标注）

1. **样本不对称**：opencode 组被排除的 8 个多为较快的设计/文档类任务（20260804 五个 Logo 设计等），
   opencode 平均可能被轻微高估——**真实差距可能略小于 32%，但 DSH 更快的方向确定无疑**
2. **任务规模未归一**：对比的是"平均任务耗时"，任务复杂度存在差异（但两组均含
   编码+测试+评审完整闭环任务，具备可比性）
3. **每节点耗时指标仅供参考**（runlog 任务的节点级 start/end 记录存在秒级失真）
4. **数据时效**：DSH 组为 20260815 当日数据；随 /cc 使用积累，可定期重算
   （看板 benchmark 区块实时反映最新数据）
