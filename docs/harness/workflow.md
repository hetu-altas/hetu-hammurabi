# 工作流编排

> 本文阐述宪章研发流程的节点流水线、门禁链、回退机制与状态固化。
> 相关实现：`.opencode/agents/charter-orchestrator.md`、`.opencode/agents/charter-*.md`。

## 一、总体流程

```
输入: /dev <任务书路径 或 一句话需求>
          │
          ▼
┌───── 节点 -1 · 任务书生成（仅一句话需求时）─────────────────────────┐
│ charter-taskwriter: 解析需求 → 资源匹配 → 按模板生成任务书            │
│ 产出: opencode_schedule/<YYYYMMDD>/<日期>任务N<名称>/任务书.md        │
└──────────────┬──────────────────────────────────────────────────┘
               ▼
┌───── 节点 0 · 校验 ──────────────────────────────────────────────┐
│ 任务书存在 / 宪章可访问 / 解析日期与任务序号 / 创建输出目录          │
└──────────────┬──────────────────────────────────────────────────┘
               ▼
┌───── 节点 1 · 分析 (charter-analyst) ────────────────────────────┐
│ 加载 charter-analysis 技能 → 读资源地图 → 匹配接口/DDL/参考代码     │
│ 产出: opencode_schedule/<YYYYMMDD>/<任务目录>/实施计划.md           │
└──────────────┬──────────────────────────────────────────────────┘
               ▼
┌───── 节点 2 · 编码 (charter-coder) ──────────────────────────────┐
│ 加载 charter-coding 技能 → 按宪章实现全部文件/脚本/依赖             │
└──────────────┬──────────────────────────────────────────────────┘
               ▼
┌───── 节点 3 · 单元测试 (charter-tester) ⚠ 硬门禁 ────────────────┐
│ 加载 charter-testing 技能 → 写测试 → 运行 → 写结果文件             │
│ 生成 .gate.json (test_passed)  →  失败回节点2，最多 3 轮          │
└──────────────┬──────────────────────────────────────────────────┘
               ▼
┌───── 节点 4 · 代码评审 (charter-reviewer) ───────────────────────┐
│ 加载 charter-coding 技能 → 只读评审 → 产出评审报告.md              │
│ REVISE 回节点2 → 重测 → 重审，最多 2 轮                          │
└──────────────┬──────────────────────────────────────────────────┘
               ▼
┌───── 节点 5 · 研发日志 (charter-logger) ─────────────────────────┐
│ 加载 charter-logging 技能 → 撰写 任务N研发日志.md                 │
└──────────────┬──────────────────────────────────────────────────┘
               ▼
┌───── 节点 6 · 资产沉淀 (charter-assetter) ───────────────────────┐
│ 加载 charter-assets 技能 → docs 新增/更新 → 登记资源地图           │
└──────────────┬──────────────────────────────────────────────────┘
               ▼
┌───── 节点 7 · 通知 (charter-notifier) ───────────────────────────┐
│ 汇总任务/文件/测试/评审/沉淀 → 钉钉 send_markdown                  │
└─────────────────────────────────────────────────────────────────┘
```

## 二、门禁链

| 门禁 | 类型 | 规则 | 载体 |
|------|------|------|------|
| 节点3 单测 | **硬** | `unit_test/test/*_result.txt` 全部通过 + `.gate.json` 中 `test_passed=true` | charter-gate 插件拦截 |
| 节点4 评审 | 软 | `评审报告.md` 结论为 APPROVE | 编排器 prompt 约束 |
| 节点5/6/7 准入 | **硬** | 门禁未开时，研发日志/流程状态写入、钉钉通知 bash 一律阻断 | charter-gate 插件拦截 |

回退规则：

- 单测失败 → 回节点 2 修复，**最多 3 轮**，仍失败停止并通知
- 评审 REVISE → 回节点 2 修复 → 重测 → 重审，**最多 2 轮**，仍不通过停止并通知

## 三、状态固化

每完成一个节点，编排器：

1. 用 `todowrite` 维护节点状态
2. 向任务目录的 `研发流程状态.md` 追加：
   ```
   时间 | 节点 | 状态(通过/失败) | 说明
   ```
3. 流程结束输出总结（改动文件数、测试通过数、评审结论、遗留事项）

## 四、输入模式（三种）

| 输入 | 处理 |
|------|------|
| 已有任务书路径 | 直接作为任务书，从节点 0 执行 |
| **一句话需求** | 节点 -1 charter-taskwriter 生成任务书（资源匹配+按模板）后，从节点 0 执行 |
| 空输入 | 扫描 `opencode_schedule/` 与 `docs/` 列出任务书供选择 |

任务书要素：
- 模板：`templates/task_book.md`
- 存放：业务项目 `opencode_schedule/<YYYYMMDD>/<任务目录>/`（以任务书名建目录）
- 命名：`YYYYMMDD任务N<名称>.md`（日期与序号供编排器解析）
- 必备章节：任务要求 / 拆分策略 / 文件清单 / 接口与格式 / 脚本 / 产出 / 单元测试 / 研发日志 / 资产沉淀 / 通知

## 五、输出目录约定

每个任务独立目录，同日多任务互不干扰：

```
opencode_schedule/<YYYYMMDD>/
└── <YYYYMMDD>任务N<名称>/          # 任务目录（以任务书名去掉 .md 命名）
    ├── <YYYYMMDD>任务N<名称>.md    # 任务书（输入，或节点-1 生成）
    ├── 实施计划.md                  # 节点1
    ├── .gate.json                   # 节点3（硬门禁状态）
    ├── 评审报告.md                  # 节点4
    ├── 任务N研发日志.md             # 节点5
    └── 研发流程状态.md              # 全流程（编排器维护）
```

## 六、编排器实现要点

- **节点顺序硬编码在系统提示词中**：前序未完成不得进入下一节点
- **节点代理通过 Task 工具按名调用**：`charter-analyst`、`charter-coder` 等
- **门禁状态由 `.gate.json` 承载**：编排器与插件共用同一事实来源
- **校验前置**：任务书/宪章/输出目录不满足条件直接拒绝启动
