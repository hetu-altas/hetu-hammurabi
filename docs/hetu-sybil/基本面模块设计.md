## 一、模块职责与零规则信号边界

- **代码职责**：结构化财务取数（**双库**：TDengine 6 表 + GreatSQL 2 表，缺失表容错）+ 文本 recall（anns_d/stock_report/irm_qa_sh）→ 双源数据视图（数据加工/字段派生非信号）→ 就绪校验 → CLI；
- **信号产出归 AI**：fundamental 信号（财务健康/盈利质量/预期差/分红能力/综合）由 AI 按 `src/prompts/fundamental-analysis.md` 研判（视图 → 模板 → LLM → validate_signal → JSONL 归档）；
- **零规则信号断言**：`test_no_rule_signal_fundamental.py`。

## 三点六、最新口径与去重策略（20260815 实跑两轮修正）

- **update_flag 语义**：tushare 更新标识，"1"=最新口径（income/cashflow 同报告期存在历史版本重复行，300750 income 203 行 vs 63 行='1'）；
- **排序策略（两次修正）**：①初版全局 update_flag='1' 优先 → 副作用：浦发现金流 2025+ 行无 '1' 标记导致 latest 错排到 2024-12-31；②修正为**报告期倒序为主 + 同报告期内 update_flag='1' 优先**（latest 永远是最新报告期），再按报告期去重；
- 反例单测：`test_income_update_flag_dedup` / `test_latest_period_without_update_flag`。

## 三点七、现金流字段补齐（20260815，用户要求补 ocf_to_profit）

- **实测根因**：tushare fina_indicator API **已不返回** ocf_to_profit/ocf_to_or/ocf_to_opincome（docstring 旧版字段），同步映射找不到源列 → 表内恒 NULL；
- **修复**：①`_TD_FIELDS["fina_indicator"]` 增加 API 实有字段 `ocfps`/`ocf_to_debt`/`ocf_yoy`/`q_ocf_to_sales`（数据真实透传）；②新增 `_derive_ocf_to_profit`：按 tushare 官方口径（经营现金流净额/营业利润）同报告期配对 cashflow.n_cashflow_act ÷ income.operate_profit（update_flag='1' 行），缺失保持 NULL——**字段派生属数据组织，非研判信号**；
- 验证：300750 2026H1 ocf_to_profit=1.08、2025 年报 1.49；002594 2026Q1=0.59（vs 2025 全年 1.47，恶化拐点）；
- 单测：`test_ocf_to_profit_derive_missing_pair`。

## 三点八、现金流数据完整性与年报交叉验证（20260815，用户建议查 Milvus 年报）

- **TDengine 现金流数据完整且可信**：300750 2025 年报 133,219,982 千元 = TDengine 133,219,982,000 元 ✓；比亚迪 59,135,544 千元 = 59,135,544,000 元 ✓（Milvus 年报分节"5、现金流"交叉验证）；
- **free_cashflow 完整**：300750 2025 年报 +871 亿；比亚迪 2025 年报 -1136 亿（重资产扩张压力）；
- **金融业态弃用**：银行（600000 现金流受存贷业务主导）/券商（601211 现金流受自营/两融波动主导，年报数字解析异常 81 万亿为 HTML 表格拼接错误）——现金流不构成盈利质量判断依据，信号中显式声明；
- **方法沉淀**：Milvus 年报分节（"5、现金流"/"合并现金流量表"/"现金流量表补充资料"）可作为财务数据交叉验证源与 evidence 引用源。
