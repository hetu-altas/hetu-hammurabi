## 一、模块职责与零规则信号边界

**职责（2026-08-12 用户确认，分析模型修正）**：本模块代码只做**取数 + 数据视图组织 + 数据就绪校验 + 候选生成（无信号）**；`technical`/`capital` 信号由 AI 输出侧（sybil-research-analyst 代理 + sybil-analysis-flow 技能 + `src/prompts/` 提示词模板，任务 11 落地）按任务 2 冻结 schema 生成。

**零规则信号红线（宪章第十四条第 1/5 款）**：
- 代码禁止实现规则打分、指标阈值判断、权重加权、评分公式、方向映射；
- 基础统计特征（均线值、涨跌幅、资金净额等）属**数据加工**，供模型研判引用，不构成分析判断；
- `unit_test/test_no_rule_signal.py` 固化双重断言（源码级扫描 + 输出结构断言），评审节点按第十四条第 5 款检查。

**代码路径**：`src/analysis/stock_analysis/`（stock_config / freshness / data_view / favourite_pool / analyze_stock）。

## 二、数据视图定义（AI 可读结构化视图，与 data_view.py 同源）

`analyze_stock(ts_code)` 输出数据视图 JSON（零信号字段，结构见任务书 4.2 / 实施计划 3.6，本设计不重复全量展开，要点如下）：

| 视图 | 子项 | 关键字段 | 来源（mercury DDL） |
|------|------|---------|--------------------|
| technical_view | daily_bars（N=60 日后复权 OHLCV）+ basic_stats | MA5/10/20/60、pct_chg_1d/5d/20d、vol_ratio_5d、annualized_vol_20d、turnover_rate/volume_ratio_latest | daily L503 / adj_factor L598 / daily_basic L757 |
| capital_view | moneyflow / margin / lhb / north / block_trade | net_mf_amount_1d/5d、rzye_latest/chg_5d、top_list_count/net_amount、hk_hold_ratio、amount_30d/premium_discount | moneyflow L796 / margin_detail L1093 / top_list L370 / top_inst L352 / hk_hold L1044 / block_trade L1007 |
| shareholder_view | cyq / holders / pledge / repurchase / top10_holders | concentration_90、holder_num_latest/chg、pledge_ratio、event_count_90d、hold_ratio_sum | cyq_perf L1028 / stk_holdernumber L65 / pledge_stat L107 / repurchase L122 / top10_holders L40 |
| data_freshness / coverage | 各源最新时点 / overall 三态 + 源清单 | — | freshness 校验输出 |
| candidate_stats | pct_chg_1d/5d/20d、amount_5d、net_mf_amount_5d、vol_ratio_5d、turnover_rate_latest | — | 候选生成数据加工字段 |

**后复权口径（R1）**：OHLC 全部 × 当日 adj_factor（Tushare 累积因子）；daily_bars 仅含因子对齐交易日；因子缺失 → adjusted=false 且不回落未复权计算（口径一致性优先，degraded 由 freshness 标注）。

## 三、基础统计特征口径（数据加工，非信号）

| 特征 | 口径（后复权收盘价口径） | 单位 | 数据不足时 |
|------|------------------------|------|-----------|
| MA5/10/20/60 | 最近 5/10/20/60 个交易日后复权 close 简单算术平均 | 元 | 不足 N 个 → 对应 ma 置 null |
| pct_chg_1d/5d/20d | (close_t / close_{t-n} − 1) × 100，n=1/5/20 交易日 | % | 不足 → null |
| vol_ratio_5d | 近 5 日均量 / 前 20 日均量（daily.vol，手） | 倍数 | 分母为 0 → null |
| annualized_vol_20d | 20 日对数收益率标准差 × √250（最近 21 个收盘价） | 年化 | 收益样本 <2 → null |
| net_mf_amount_1d/5d | moneyflow.net_mf_amount 最近 1/5 日累计 | 万元 | 无数据 → null + missing 标注 |
| turnover_rate/volume_ratio_latest | daily_basic 最新期次直读 | % / 倍数 | 无数据 → null |
| 大宗折溢价 premium_discount_30d | 30 日大宗加权均价 vs 同期收盘价均值偏离 | % | 无大宗/无收盘参考 → null |
| 股东户数变化 holder_num_chg | 最新期次 vs 上一期次 (now/prev − 1) | 比率 | 仅一期 → null |

> 特征开关 `FEATURE_STATS_ENABLED`（stock_config.py）默认全开（待确认T11）；全部特征为数据加工，
> 趋势/动量等**排列判断归 AI**，代码不输出"多头/空头/超买/超卖"等结论。

## 四、AI 研判流程（AI 输出侧）与分节要点

**研判流程（任务 11 落地，本任务交付输入侧）**：取数脚本输出数据视图 → 模板变量填充（{{ts_code}}/{{data_view}}/{{trade_date}}/{{pool_context}}/{{data_freshness}}）→ sybil-research-analyst 代理（system prompt 引用模板路径）→ sybil-analysis-flow 技能加载对应模板 → LLM 研判 → 信号校验（任务 2 validate_signal）→ 记录。**1 条流水线 = 1 次分析任务，承载标的集合 1~N 只（内部批量 + AI 研判，批量 ≠ 多次实例化，架构 4.5.1/4.5.4）**。

**分节要点（docs/skills/sybil-analysis-flow/个股数据分析分节.md，与代码同源）**：
- 数据视图读取规范（三视图结构/字段口径与单位/daily_bars 行序/后复权口径）；
- AI 研判提示词框架：技术面四维=**趋势/动量/波动/量价**、资金面五维=**资金流/两融/龙虎榜/北向/大宗**（引用 `src/prompts/` 对应模板，非规则公式）；
- 信号输出要求：任务 2 冻结 11 字段 schema；signal_type 初版枚举 technical=`technical_momentum`/capital=`capital_flow`；evidence 引用数据视图条目；meta.data_freshness/data_coverage 取自视图标注；
- 数据就绪校验与新鲜度声明规则（下节）；query_batch 批量调用方式（第五节）。

**提示词模板集（代码资产，`src/prompts/`，4 个草稿）**：data-view-guide（公共层·视图解读）、signal-output（公共层·信号组装）、technical-analysis（模块层·技术面）、capital-analysis（模块层·资金面）——markdown + frontmatter 五字段（name/version/module/depth/variables）+ 正文六段（角色/输入/分析任务/分析要求/输出格式/约束）+ `{{变量}}` 占位符；变量与数据视图 JSON 字段绑定一致（T12 默认稿：{{ts_code}}↔ts_code、{{data_view}}↔三视图、{{trade_date}}↔trade_date、{{pool_context}}↔关注池 pool、{{data_freshness}}↔data_freshness/coverage）；**无硬编码股票代码/日期/数值**（test_prompt_template 正则扫描断言）；T13 默认按**通用版**交付（depth=light+standard，不拆三份物理文件）；任务 11 随技能私有发布至 `.opencode/skills/sybil-analysis-flow/prompts/`。

## 五、批量查询契约演进与候选生成设计（补充 1）

**契约演进（向后兼容）**：`src/data_access/tdengine_access.py` **仅新增** `query_batch(super_table, ts_codes: List[str], start_date, end_date, fields=None) -> List[Tuple]`：
- SQL：`SELECT {fields} FROM {super_table} WHERE ts_code IN ('c1','c2',...) AND ts >= '{start} 00:00:00' AND ts < '{end+1日} 00:00:00'`；
- 红线：ts_codes 逐项白名单校验（任一非法**整体拒绝**）、None/空列表/缺日期 ValueError（禁止全表扫描）、半开区间同 query、with 上下文 + RuntimeError 包装、只读（无写方法）；
- 分批职责：`query_batch` 列表即批，调用方切分（默认 `BATCH_SIZE=400`，每批 300~500 只，待确认T8）；
- `__init__.py` 包级导出追加 query_batch；**既有 query/query_one/query_all/recall 签名与行为一律不改写**（任务 2 回归 90/90 全绿）；
- 契约文档 `docs/数据访问层与信号标准设计.md` 2.1/2.4 节 + 第 9 节修订记录已同步（T3-1/T3-2 条目）。
- **GreatSQL 侧不新增 IN 封装**（设计决策）：query_all 参数化 %s 已满足慢变量表单标的查询场景；批量 IN 场景有限，如后续需要（按报告期批量取 top10_holders）留待评估。

**候选生成（analyze_stocks，无信号）**：
- 定位（架构 4.5.4）：**代码级候选生成工具 + 流水线步骤②批量取数与数据视图组织工具**（筛选工具、无信号、非流水线本体）；候选清单基于基础统计特征排序（默认 `CANDIDATE_SORT_KEY=pct_chg_20d` 降序，排序键参数化），直接作为同一条流水线的聚焦子集输入（S1 日频例行/S5 按需场景）；
- 分批：`batches = [codes[i:i+batch_size] ...]`，每批 query_batch×3（daily/adj_factor/moneyflow）；批内单股独立标注（某股 core 过期只影响该股 coverage）；批内单股异常 error_count++ 继续；批次查询异常 error_count += 批大小并跳过该批；
- 批量模式默认**不组织 shareholder_view**（设计决策：慢变量逐股成本高、非候选排序所需）；
- 性能目标（验收 6）：关注池 ≤100 只单批秒级、全市场 5525 只（400/批 → 14 批×3 次查询）分钟级；真实环境抽样冒烟记录耗时（研发日志），mock 下以分批断言为准。

> **预筛参数数据核对口径注记（2026-08-13 用户确认）**：代码级候选预筛参数（批大小/排序特征/视图窗口等）仅做**数据核对**（轻量统计，验证数据覆盖与取数正确性），**非策略回测**；本体系验证范式 = 前向验证 + 复盘归因（架构 1.2/3.7 节），候选预筛参数不承担策略有效性论证。
